# P7 (CP2K s/step) — **보류. 패키지에 넣지 않았다.**

lead 가 engineer §R23 제안 ②를 승인해 재실행 패키지에 편승시키라고 지시했으나,
**구현 중에 사용자 수준 제약과 충돌하는 것을 발견해 착수를 멈췄다.**

## 충돌하는 것
```
tests/test_accounts.py:210  test_only_gaussian_and_xtb_remain
   "🔴 사용자 요구: 모든 DFT/반경험 방법론은 VASP·Gaussian·xtb 로."
   → 계산 항목은 {P1, P1b, P5, P3} 뿐이어야 한다고 단언한다.

tests/test_integration_paths.py:223  test_cp2k_layer_is_fully_removed
   → payload/*.sh 에 CP2K 참조가 있으면 실패한다.
```
근거 ADR: **ADR-037 / ADR-038 / ADR-039** (λ_out 재결 → **CP2K 요구 소멸**).

## 왜 테스트를 고치지 않았나
🔴 **이 두 테스트는 사용자가 직접 건 제약을 코드로 굳힌 것이다.**
그것을 내가 지우면 **사용자 결정을 코더가 되돌리는 것**이 된다. 그리고 이 팀에서
가장 비싼 실패는 "가드를 조용히 없애는 것"이었다.
⟹ **lead 판정 대기.** 판정이 "넣어라"면 이 파일을 `payload/` 로 옮기고 두 테스트를
**사유와 함께** 갱신하면 된다(작업 10분).

## 이 스크립트가 이미 반영하고 있는 것 (proposer §37 / engineer §R23.3)
- 🔴 `$CP2K_DATA_DIR` 가 없으면 **측정하지 않는다.** CP2K 는 그 경우 죽지 않고
  **조용히 기본값으로 다른 계산을 한다** — 그 단가는 우리가 물은 질문의 답이 아니다.
  *"잘못된 숫자보다 없는 숫자가 낫다."*
- 배너(`--version`)·`CP2K_DATA_DIR`·입력 에코를 회신에 남긴다.
- `METHOD XTB` 확인은 **"쓸 수 있나"가 아니라 "쓰면 안 되는 걸 확인"** 이다
  (CP2K 내장 xTB 는 GFN1 이라 축 2 와 독립이 아니다). **이 결과로 CP2K-XTB 경로를 만들지 마라.**
