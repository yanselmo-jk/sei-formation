## Deployed-package fingerprint guard (new this pass)

The `.qsub` now asserts, right after it sources `common.sh` and before `sei_job_main` starts the
payload, that `$SEI_PKG_ROOT`'s own recomputed `package_fingerprint` (via `common.sh`'s own
`sei_pkg_fingerprint()` -- the SAME workdir-aware exclusion logic its stage-checkpoint mechanism
already uses, per critic17's pre-build note, so a renamed `--workdir` doesn't false-alarm)
equals `b94510460851012e` (the fingerprint of the source tree this pair was built from) —
refuses with exit 9 and a message naming the two known false-alarm causes otherwise. This exists
because the `.qsub` references a PATH, not a package: if a stale package were deployed at that
path, this job would silently run with old code (missing e.g. `recorrect=never`'s corrector
fix) and nothing would flag it. Lands in the GENERATED QSUB per the lead's explicit scoping
(zero shared-file blast radius; wiring this into `common.sh` itself was considered and
deliberately deferred to its own slot). This guard is this tool's OWN addition (inserted via
string surgery on the already-rendered qsub text, not reused scheduler/template code), so it is
stripped before the byte-identical-to-the-original-`U56_RB_scan.qsub` comparison
(`tests/test_build_wave1_rb_submission.py`) and tested separately by extracting and RUNNING it.
`.cmd.sh` is untouched by this guard and is now byte-identical to the original, unmodified.
